# Session Handoff to Devspace

Prepares a session handoff by writing a summary and params file that the out-of-sandbox `run-handoff.sh` script will consume. The skill does **no SSH or network operations** — those are handled by the script.

## Parameters

If the skill was invoked with an argument (e.g. `/handoff my-devspace`), that string is the preferred devspace name. Write it into the params file as `DEVSPACE_NAME`.

If no argument was given, attempt to resolve the devspace name by running:

```bash
coder list --output json 2>/dev/null
```

- **One workspace found**: use its name
- **Multiple found**: ask the user which one to use
- **None or command fails**: write `DEVSPACE_NAME=` (empty) and add a comment in the params file telling the script to prompt the user

---

## Step 0: Resolve the Session Slug

Determine a human-readable identifier. Use the session's `/rename` name if set; fall back to a timestamp.

```bash
SESSION_ID="$CLAUDE_CODE_SESSION_ID"
SESSION_FILE=$(find ~/.claude/projects -name "${SESSION_ID}.jsonl" 2>/dev/null | head -1)

SESSION_NAME=""
if [ -n "$SESSION_FILE" ]; then
    SESSION_NAME=$(python3 -c "
import json, sys
name = ''
with open(sys.argv[1]) as f:
    for line in f:
        d = json.loads(line)
        if d.get('type') == 'custom-title':
            name = d.get('customTitle', '')
print(name)
" "$SESSION_FILE" 2>/dev/null)
fi

# Sanitize: lowercase, spaces → hyphens, strip non-alphanumeric
SESSION_SLUG=$(echo "$SESSION_NAME" | tr '[:upper:]' '[:lower:]' | tr ' ' '-' | tr -cd '[:alnum:]-_')

# Fall back to timestamp if no /rename name
if [ -z "$SESSION_SLUG" ]; then
    SESSION_SLUG=$(date +%Y%m%d-%H%M%S)
fi
```

---

## Step 1: Write the Handoff Summary

Create `~/claude-handoffs/pending/<SESSION_SLUG>.md` with a comprehensive summary of the session.

The file must cover:

```markdown
# Claude Session Handoff — <YYYY-MM-DD HH:MM>

## Session Goals
What were we trying to accomplish in this session?

## Current Status
- What is done
- What is in progress (and exactly where it was left off)
- What is blocked and why

## Key Findings & Insights
Important discoveries, root causes identified, design decisions made.

## Files Modified
List every file changed with a one-line description of what changed and why.

## Pending Work
Ordered list of remaining tasks with enough detail to resume without re-reading the conversation.

## Environment-Specific Tasks
Commands that must be re-run in the new environment (builds, test runs, etc. do NOT carry over):
- Any buck2 build commands that were in progress or need to be run
- Any test commands with their full invocation
- Any local server processes that were running

## Branch & Context
- Branch: <current branch>
- Jira: <ticket if known>
- PR: <PR URL if one exists>

## Resume Instructions
The specific next action to take when resuming, written so a fresh Claude instance can
pick up immediately without re-reading the conversation.
```

Record the path as `HANDOFF_LOCAL` (e.g. `~/claude-handoffs/pending/ps5-triage.md`).

---

## Step 2: Determine Devspace Name

```bash
BRANCH=$(git rev-parse --abbrev-ref HEAD)
# Preferred (fallback) worktree path. The runner checks the devspace for an
# existing worktree on $BRANCH first; if one is found (e.g. left over from a
# prior handoff), it is reused and this preferred path is ignored. Only when
# no worktree exists for the branch will this path be created.
WORKTREE_RELPATH="worktrees/handoff-${SESSION_SLUG}"
TMUX_SESSION="claude-${SESSION_SLUG}"
```

Resolve `DEVSPACE_NAME` per the Parameters section above.

---

## Step 3: Write the Params File

Write `~/claude-handoffs/pending/<SESSION_SLUG>.params` as a bash-sourceable file:

```bash
# Handoff params — generated by /handoff skill
# Run ~/.claude/skills/handoff/run-handoff.sh to execute

DEVSPACE_NAME=<resolved name or empty>
BRANCH=<current branch>
SESSION_SLUG=<slug>
HANDOFF_LOCAL=<absolute path to the .md file>
# Preferred path; the runner reuses an existing worktree on $BRANCH if one is
# present on the devspace, and only falls back to creating this path otherwise.
WORKTREE_RELPATH=<e.g. worktrees/handoff-ps5-triage>
TMUX_SESSION=<e.g. claude-ps5-triage>
```

If `DEVSPACE_NAME` could not be resolved, leave it empty and add a comment:
```bash
# DEVSPACE_NAME was not resolved — edit before running, or pass as argument:
#   run-handoff.sh <slug> my-devspace-name   (not yet supported; edit the file)
DEVSPACE_NAME=
```

---

## Step 4: Report to the User

Print a summary of what was written and the command to run:

```
Handoff files written:

  ~/claude-handoffs/pending/<SESSION_SLUG>.md     ← session summary
  ~/claude-handoffs/pending/<SESSION_SLUG>.params  ← transfer params

To execute the handoff, run in a terminal outside the sandbox:

  ~/.claude/skills/handoff/run-handoff.sh

The script will:
  1. Start the devspace if stopped
  2. Push the handoff file
  3. Reuse an existing worktree on branch '<BRANCH>' if one is present on the
     devspace (e.g. from a prior handoff); otherwise create one at
     '~/<WORKTREE_RELPATH>'
  4. Start claude --dangerously-skip-permissions in tmux session 'claude-<SESSION_SLUG>'
     with the resolved worktree as its working directory
  5. Archive these files on success

To attach once it completes:
  coder ssh <DEVSPACE_NAME> -- tmux attach -t claude-<SESSION_SLUG>
```

If `DEVSPACE_NAME` was not resolved, tell the user to edit the params file before running.
